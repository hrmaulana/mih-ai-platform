# Renstra Digital Implementation Plan

> **For Hermes:** Execute this plan phase-by-phase. Preserve the current Renstra page as-is for side-by-side comparison; do not redirect or replace it.

**Goal:** Add a new “Renstra Digital” submenu and route that presents the agreed narrative flow with purposeful scroll-triggered animation, while leaving the current Renstra experience available unchanged.

**Architecture:** Build a separate React page/component and stylesheet using existing Renstra data modules wherever they faithfully represent the source. Add a new route and navigation item alongside the existing Renstra menu. Use native scroll + IntersectionObserver for chapter activation and Anime.js for selective SVG/number/card motion; retain keyboard access, reduced-motion behavior, and mobile-friendly normal scrolling.

**Tech Stack:** React 19, React Router 7, TypeScript, Vite, Anime.js (current major verified at implementation time), existing CSS/IntersectionObserver. Do not add Lenis or full-page snap in the first iteration.

---

## Goals and acceptance criteria

- Existing `/renstra-pmp` and its submenu remain intact and directly reachable.
- A separate submenu named **Renstra Digital** opens a new route, preferably `/renstra-digital`.
- Both versions are usable for management comparison without overwriting each other.
- Digital page follows the agreed narrative: mandate → achievements/context → challenges/opportunities → strategic response → operating model → results/IKU → implementation support → closing commitment.
- Scroll animations clarify sequence or relationships, never gate content, and do not hijack normal scrolling.
- `prefers-reduced-motion` disables nonessential motion; content and final values remain visible.
- Responsive at narrow viewport; navigation and interactive visualizations remain keyboard-accessible.
- Build/lint pass and both old and new routes return successfully in local app verification.
- For the overall funding total, use the sum of the “Total” column in the source table as authoritative (approximately Rp321.408323 M based on the transcribed unit totals). Do not derive the headline total by summing annual allocation figures.

## Current context

- Existing Renstra route is registered twice in `frontend/src/App.tsx` at the portal route trees as `/renstra-pmp` and renders `frontend/src/pages/portal/RenstraPmp.tsx`.
- Existing page already includes `IntersectionObserver` reveal, reduced-motion detection, scroll progress/nav activation, tree focus, IKU charts, process map, and funding chart.
- Existing Renstra data is split across `frontend/src/data/renstra/{meta,content,units,performance,tables,processMap}.ts`.
- `frontend/package.json` currently has no Anime.js dependency.
- Existing navigation menu source has not yet been definitively identified; inspect its actual component/data before adding the second item. Do not infer it from the route alone.
- Funding headline rule confirmed by user: use the sum of the source table’s “Total” column as the authoritative total, not the sum of the yearly allocations. Based on transcribed figures, unit totals add to Rp321.408323 M (display rounded appropriately). For the new page, derive/show the headline from this column and do not substitute Rp329.6 M (the sum of annual bars). The legacy page is to remain untouched for comparison.
- Source PDF is `docs/references/Renstra-Dep-PMP-2025-2029.pdf`.

## Proposed implementation

1. Create a new independent `RenstraDigital.tsx` + `RenstraDigital.css`, reusing source-backed datasets but not altering the current page’s behavior or styling.
2. Add a new route in both relevant route trees and add a new navigation item adjacent to the existing Renstra item. Confirm the actual menu component and access rules first.
3. Build narrative chapters as focused sections. Use an explicit page-specific chapter metadata array as the single source for chapter IDs, labels, titles, and transition text to avoid duplicate nav/section definitions.
4. Add Anime.js for a small set of controlled effects: hero/mandate diagram reveal, paired achievement/context counters, strategy theme stagger, process flow line/steps, performance chain highlight, and funding chart entrance. Trigger once on intersection; do not run per-scroll-frame timelines by default.
5. Keep source notes and expandable details for full tables/process descriptions. Main narrative should stay concise; avoid copying the entire Renstra tables into the reading flow.
6. Respect reduced motion before registering/playing animations. Use semantic static SVG/HTML as the baseline; motion enhances it. Add teardown/cancel behavior for component unmount and route changes.
7. Validate existing and new routes side-by-side, responsive layouts, focus behavior, no-JS-like visible content fallback, and source figures.

### Tahap 3 — Define digital narrative chapters and baseline layout

**Objective:** Implement the agreed narrative as semantic, readable sections before adding animation.

**Files:**
- Create `frontend/src/data/renstra/digitalNarrative.ts` for chapter metadata/copy and source references, unless an existing content pattern makes a local typed constant preferable.
- Modify `RenstraDigital.tsx` and `RenstraDigital.css`.

**Chapter structure and content:**
1. Mandat: PMP connects national direction and implementation; include the upstream-to-control cycle.
2. Starting point: selected 2020–2024 achievements + explicit unresolved outcomes/control challenge.
3. Challenges/opportunities: group diagnosis into external change, transformation needs, and PMP’s institutional strengths.
4. Strategic response: group detailed strategies into 4–5 themes while keeping source detail expandable.
5. Operating model: six units/functions and process loop; expandable unit detail references source pages.
6. Results: strategy → outputs/outcomes → four IKUs with targets 2025–2029.
7. Implementation support: SDM, regulation, program, and funding. Use the source table’s “Total” column as the authoritative overall funding total; show annual allocations separately and do not replace the table total with a sum of yearly values.
8. Closing commitment and link to source PDF.

**Design requirements:**
- Editorial, institutional visual identity consistent with current Renstra palette; establish scope and design tokens locally so current design is unaffected.
- Sticky chapter navigation/progress indicator with working anchors; on small screens use horizontally scrollable chapter chips or compact menu.
- Content available on initial render; no `opacity:0` dependency on JavaScript.
- Tables/details are progressive disclosure, with source-page notes.

**Verification:** Build/lint; manual review of all chapter anchor targets and heading outline; cross-check numerical claims against source data/PDF.

### Tahap 4 — Add Anime.js dependency and accessible animation primitives

**Objective:** Introduce animation in a reusable, opt-in way with cleanup and reduced-motion support.

**Files:**
- Modify `frontend/package.json` and lockfile using the repository’s package manager.
- Create `frontend/src/pages/portal/renstraDigitalMotion.ts` (or colocate small helpers if project conventions favor fewer files).
- Modify `RenstraDigital.tsx`/CSS to apply animation hooks/classes.

**Implementation requirements:**
- Inspect installed/latest Anime.js API and repository lockfile first; use supported version/API, avoid stale v3 syntax if v4 is current.
- Use an IntersectionObserver once-per-element trigger. Keep normal native scroll; do not introduce Lenis, snap, or scroll hijacking.
- Animate only transform/opacity/stroke/number display where suitable; avoid layout-thrashing properties.
- Reduced-motion path renders final state immediately and skips animation setup.
- Each effect has cleanup: disconnect observers, cancel/terminate Anime.js instances, avoid duplicate triggers under React StrictMode.
- If JS/animation setup fails, static baseline remains legible.

**Verification:** `npm run build`, `npm run lint`; check reduced-motion emulation; test route mount/unmount repeatedly and verify no repeated animation or console errors.

### Tahap 5 — Implement purposeful chapter-specific motion

**Objective:** Use animation to explain the narrative relationships without distracting from reading.

**Files:** `RenstraDigital.tsx`, `RenstraDigital.css`, and motion helper if needed.

**Effects:**
- Hero: stagger text and draw the mandate cycle, once.
- Starting point: animate selected counters to exact targets; animate challenge/capaian pairing together.
- Strategy themes: stagger cards when entering viewport; detail text does not animate into hidden state.
- Operating model: draw a connecting line or highlight process stages; provide static equivalent and avoid conveying meaning by color alone.
- Results chain: highlight path on focus/click; preserve keyboard behavior and existing information density limits.
- IKU: selected chart path/value transitions with text/table alternative.
- Funding: animate bars from baseline once; make data scope and discrepancy explicit; retain table/source link.
- Transitions: small section separator motif only if it improves orientation.

**Guardrails:** No autoplay video/parallax, no full-page snap, no continuous loops, and no movement required to reveal text. Keep motion durations restrained and consistent; cap animation count on mobile if performance warrants.

**Verification:** Manual scroll through all sections on desktop/mobile, keyboard-only operation, `prefers-reduced-motion`, CPU throttling if available, and browser console check.

## Risks and decisions

- **Anime.js version/API:** verify actual package release, install behavior, and lockfile before coding; don't assume examples from a different major version.
- **Comparison parity:** content grouping will differ from current page, but source basis and key numbers must match. Cite PDF file page and printed document page consistently.
- **Funding:** user confirms the sum of the source table’s “Total” column is the authoritative overall total. Display that as the headline; annual allocation values may be shown by year but must not be used to replace or recalculate the headline total.
- **Scroll/anchor offsets:** sticky top nav may obscure section headings. Add `scroll-margin-top` and verify on mobile.
- **Large tables/process detail:** keep them expandable to preserve concise narrative and page performance.
- **Security/permissions:** mirror existing route guards and menu visibility exactly; no public route if old Renstra is restricted.
- **Deployment:** plan covers local implementation/verification only. No commit, push, or production rollout unless explicitly requested.
